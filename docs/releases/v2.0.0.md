LogDoc rebuilt from scratch: a single Go binary on top of ClickHouse,
Apache 2.0.

![Live architecture map built from logs](https://raw.githubusercontent.com/LogDoc-org/logdoc/main/docs/img/topology.png)

## Highlights

- **Architecture map from logs alone.** Services sharing trace/correlation
  ids and peer fields connect themselves into a live directed map — no
  agents, no mandatory tracing. Click an edge to see the live logs of that
  connection; failing services and edges light up red. Export the current
  map as Mermaid or Markdown for your docs.
- **MCP built in.** The server speaks Model Context Protocol over HTTP:
  any agent (Claude Code or anything MCP) investigates your system through
  the same three tools the UI uses — `query_logs`, `get_topology`,
  `get_service_card`. In the demo, an agent root-causes a cascading
  failure unattended in under a minute.
- **Search + live tail UI** — filters, field chips, infinite scroll,
  WebSocket live tail.
- **Ingest**: HTTP JSON, OTLP/gRPC (`:4317`), and the byte-compatible v1
  protocol on TCP/UDP `:9999` — existing LogDoc v1 appenders work
  unchanged.
- **Notifications**: error-burst and service-silence rules over the live
  stream, delivered to Telegram, webhook, or email.

## Quick start

```bash
git clone https://github.com/LogDoc-org/logdoc && cd logdoc
docker compose -f deploy/docker-compose.yml up -d --build
```

UI at http://localhost:9001. Try the incident demo:
`deploy/demo-incident.sh`, then ask an MCP-connected agent
*"why is checkout failing?"*.

Binaries below expect a reachable ClickHouse (see
[docs/getting-started.md](https://github.com/LogDoc-org/logdoc/blob/main/docs/getting-started.md));
the compose stack is the batteries-included path.

Migrating from v1? See
[docs/migration-v1.md](https://github.com/LogDoc-org/logdoc/blob/main/docs/migration-v1.md).
