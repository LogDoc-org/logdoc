Seven features on top of the v2.0.0 launch: full functional parity with
LogDoc v1 — and the map got smarter.

## Highlights

- **Deploy markers from logs.** A `version` field (or a deploy-style
  message) becomes a recorded version change on the service card —
  "2.3.1 deployed, seconds later the first errors". API:
  `GET /api/v1/deploys`.
- **Topology diff — what changed?** New and silent services and links,
  error-rate jumps versus the previous window, and deploys in one report:
  the **Changes** toggle on the map, `GET /api/v1/topology/diff`, and the
  `get_topology_diff` MCP tool for agents.
- **Pipelines: structure on ingest.** Server-side parsing before storage,
  search, the map and alerts see the entry: `grok` (built-in pattern
  library), `regex`, `json`, `severity`, `set`, `drop`, with `when`
  selectors. A raw nginx access line becomes queryable fields, gets its
  real severity, and puts the upstream service on the map.
- **Smarter alerts, managed at runtime.** `error_threshold` rules can
  carry composite `match` conditions (nested `and`/`or`, string and regex
  ops on message and fields), `max_fires` retires noisy rules. Create,
  edit and delete rules from the new **Rules** tab or
  `/api/v1/notify/rules` — no restart. New delivery channel: Kafka.
- **Users and roles.** Bootstrap with an API key, then create accounts on
  the **Access** tab: admin/member roles, JWT sessions, revocable personal
  `ldt_...` tokens for scripts and CI. No users configured = open dev
  mode, exactly as before.
- **More ways in.** Built-in syslog listener (RFC 3164/5424 auto-detected,
  TCP + UDP), journald export format over UDP (binary fields included),
  and the Python stdlib `logging` Socket/DatagramHandler wire formats —
  no client library needed.
- **Plugin SDK v2.** External plugins are standalone executables the core
  launches and supervises over gRPC: `source` plugins stream entries in,
  `pipe` plugins become notification channels. Any language; contract in
  `pkg/sdk/proto/plugin.proto`, reference implementation in
  `plugins/syslog-source`.

## v1 parity

With this release v2 covers everything the v1 community server actually
did — protocols (syslog, journald, Python, native `ld_format`), channels
(Telegram, webhook, email, Kafka), composite watchdog-style rules, users
and roles, and an external-plugin story. See
[docs/migration-v1.md](https://github.com/LogDoc-org/logdoc/blob/main/docs/migration-v1.md).

## Quick start

```bash
git clone https://github.com/LogDoc-org/logdoc && cd logdoc
docker compose -f deploy/docker-compose.yml up -d --build
```

UI at http://localhost:9001. Binaries below expect a reachable ClickHouse
(see
[docs/getting-started.md](https://github.com/LogDoc-org/logdoc/blob/main/docs/getting-started.md));
the compose stack is the batteries-included path.
